## Git

Git is used for version control and helps multiple people work on the same project.

**Upstream** refers to the remote repository that our local project gets updates from.

Before starting work, we should pull the latest changes:

```text
git pull
```

This makes sure we are working with the latest version and reduces the chances of merge conflicts.

A **merge conflict** happens when Git cannot automatically combine changes made by different people, so we have to manually decide which changes should be kept.

## Maven Project

The `target` folder is created by Maven when we compile or build the project. It contains generated files, so we normally do not edit anything inside it.

The `pom.xml` is the main configuration file for a Maven project.

The basic structure starts with:

```xml
<?xml version="1.0" encoding="UTF-8"?>

<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0
         http://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>
```

The project information is then given using:

```xml
<groupId>com.example</groupId>
<artifactId>firstproj</artifactId>
<version>1.0-SNAPSHOT</version>

<name>firstproj</name>
<url>http://www.example.com</url>
```

Here, `groupId` identifies the group or organization, `artifactId` identifies the project, and `version` tells us which version of the project is being used.

The Java compiler version can be specified inside `properties`:

```xml
<properties>
    <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
    <maven.compiler.source>1.7</maven.compiler.source>
    <maven.compiler.target>1.7</maven.compiler.target>
</properties>
```

The `dependencies` section is used to add libraries required by the project. In our example, JUnit was added for testing:

```xml
<dependencies>
    <dependency>
        <groupId>junit</groupId>
        <artifactId>junit</artifactId>
        <version>4.11</version>
        <scope>test</scope>
    </dependency>
</dependencies>
```

The `build` section contains plugins that Maven can use for different tasks:

```xml
<build>
    <pluginManagement>
        <plugins>
            <plugin>
                <artifactId>maven-clean-plugin</artifactId>
                <version>3.1.0</version>
            </plugin>

            <plugin>
                <artifactId>maven-compiler-plugin</artifactId>
                <version>3.8.0</version>
            </plugin>

            <plugin>
                <artifactId>maven-surefire-plugin</artifactId>
                <version>2.22.1</version>
            </plugin>

            <plugin>
                <artifactId>maven-jar-plugin</artifactId>
                <version>3.0.2</version>
            </plugin>
        </plugins>
    </pluginManagement>
</build>
```

These plugins are used for things such as cleaning the project, compiling code, running tests and creating the JAR package.

## Swing and Thread Safety

One important thing about Swing is that its GUI components are generally **not thread-safe**.

This means multiple threads should not directly modify Swing components at the same time because it can cause inconsistent or unpredictable behaviour.

Swing therefore uses the **Event Dispatch Thread (EDT)** for handling GUI events and updating components.

For example:

```java
SwingUtilities.invokeLater(() -> {
    // GUI code
});
```

This puts the GUI-related task onto the EDT.

The whole application does not have to use only one thread. Long-running tasks can be performed in background threads, while changes to the GUI are made on the EDT.

## Multithreading and Thread Safety

A **process** is a running program, while a **thread** is a path of execution inside a process.

Multithreading allows multiple tasks to make progress at the same time, but it can create problems when threads access the same resource.

A **race condition** happens when the result depends on the order or timing of different threads.

Resources can also be **locked** so that only one thread accesses them at a time. However, incorrect locking can cause threads to wait for each other and potentially create a deadlock.

Overall, I learned that multithreading can make applications more efficient, but it also requires careful handling of shared resources. I also understood that Swing uses a dedicated GUI thread because its components are not generally thread-safe.
