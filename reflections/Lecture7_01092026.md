## Explaining Project 1

Project 1 was about drawing shapes on a panel. While explaining it, the main point was that a shape like a triangle is not just three points, it is really three lines (edges), and each line comes from an equation.

## Why a triangle needs at least 3 equations

A straight line can be written as one equation. If we only have **2 equations**, we only have **2 lines**. Two lines can at most cross at one point, so they cannot close a shape.

To make a triangle we need **3 lines**, which means **3 equations**. The three lines then meet at three corners and enclose an area.

```text
2 lines  -> 1 crossing point, open shape, no triangle
3 lines  -> 3 corners, closed shape, triangle
```

## The equation form Ax = B

A system of linear equations can be written in matrix form:

```text
A x = B
```

Here:

- `A` is the matrix of coefficients (the numbers in front of the unknowns)
- `x` is the column vector of unknowns
- `B` is the column vector of the right hand side values

Solving the system means finding `x`.

### Example

Take two equations:

```text
2x + 3y = 8
1x - 1y = 1
```

In `Ax = B` form:

```text
A = | 2   3 |      x = | x |      B = | 8 |
    | 1  -1 |          | y |          | 1 |
```

Dimensions:

- `A` is `2 x 2` (2 rows, 2 columns)
- `x` is `2 x 1`
- `B` is `2 x 1`

The rule is that the number of columns of `A` must match the number of rows of `x`. In general, for `n` equations with `n` unknowns, `A` is `n x n`, and `x` and `B` are `n x 1`.

So drawing shapes with lines is connected to linear algebra, because finding where lines meet (the corners) is really solving `Ax = B`.

## How Maven helps organise large code

When a project gets bigger, there are many things to check every time we build, like compiling all files, running all tests, and packaging the result.

Maven helps because it gives a **fixed structure** and **standard commands**, so every build does the same steps in the same order:

```text
mvn clean     -> remove old build output
mvn compile   -> compile the source code
mvn test      -> run all tests
mvn package   -> build the JAR
```

Instead of remembering and running each check by hand, Maven runs them as **phases**. If one phase fails (for example a test), Maven stops, so a broken change does not move forward. This keeps large code bases consistent.

## Erasing a circle in a JPanel

In Swing we do not really "delete" something we drew. The panel just redraws everything in `paintComponent`. To make a circle disappear, we can draw over it using the **background colour**:

```java
g2d.setColor(getBackground());
g2d.fillOval(x, y, d, d);
```

This paints the same area with the background colour so the circle is not visible any more.

A cleaner way is to keep a list of the circles we want to show, remove one from the list, and then call `repaint()` so the panel redraws only what is left.

## Remembering which circle was drawn last

If we want to erase the **last** circle, we need to know the order the circles were added.

The simple idea is to store each circle in a list as we draw it:

```java
List<Circle> circles = new ArrayList<>();
circles.add(new Circle(x, y, d));
```

The last drawn circle is the last element:

```java
circles.remove(circles.size() - 1);
repaint();
```

This is basically **last in, first out** behaviour, which leads to the next topic.

## Stack vs Queue

Both are ways to store items, but they differ in the order items come out.

- **Stack** — Last In, First Out (LIFO). The last item added is the first removed. Operations are `push` and `pop`. Good for "undo the last thing".
- **Queue** — First In, First Out (FIFO). The first item added is the first removed. Operations are `enqueue` and `dequeue`. Good for processing things in the order they arrived.

```text
Stack:  push A, push B, push C  ->  pop gives C, then B, then A
Queue:  add  A, add  B, add  C  ->  remove gives A, then B, then C
```

For erasing the last circle, a **stack** fits, because we always remove the most recent one.

## Project: circles on right click, connected by arrows

The rough steps discussed were:

1. Create the `JFrame` window and add a `JPanel` for drawing.
2. Add a mouse listener. On a **right click**, create a new circle at the click position and add it to the list, then `repaint()`.
3. In `paintComponent`, loop through the list of circles and draw each one with `fillOval` or `drawOval`.
4. To connect circles, detect a **drag**: record the circle where the drag starts and the circle where it ends.
5. Store that pair as an arrow (a link between two circles).
6. In `paintComponent`, also loop through the arrows and draw a line from the centre of the start circle to the centre of the end circle, with a small triangle at the end for the arrow head.

This is basically building a simple graph editor.

## Binary Tree

A **binary tree** is a tree data structure where each node has **at most two children**, usually called the left child and the right child.

Common terms:

- **Root** — the top node, it has no parent.
- **Parent** — a node that has children.
- **Child** — a node that comes from a parent.
- **Leaf** (or end node) — a node with no children.
- **Internal node** — a node that has at least one child.
- **Edge** — the link between a parent and a child.
- **Depth** of a node — how many edges from the root down to that node.
- **Height** of the tree — the longest path from the root to a leaf.
- **Subtree** — a node together with all of its descendants.

```text
        A          <- root
       / \
      B   C        <- internal nodes
     / \   \
    D   E   F      <- leaves (end nodes)
```
