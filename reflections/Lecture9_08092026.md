## 1. Working with Java's Data Structures

Java provides the **Collections Framework** as a collection of reusable
interfaces, implementations, and utility operations for storing and
manipulating groups of objects. The appropriate structure depends on
whether the program needs ordering, uniqueness, sequential processing,
or key-based lookup.

### Ordered Collections --- `List`

A `List` preserves a sequence of elements and normally allows duplicate
values.

-   `ArrayList` --- dynamically resizable array with efficient indexed
    access.
-   `LinkedList` --- linked-node structure that can also provide queue
    and deque behavior.

``` java
List<String> students = new ArrayList<>();

students.add("Aarav");
students.add("Momo");
```

### Collections of Distinct Values --- `Set`

A `Set` is intended for situations in which duplicate elements should
not be stored.

-   `HashSet` --- hash-based storage with no guaranteed iteration order.
-   `LinkedHashSet` --- preserves insertion order.
-   `TreeSet` --- maintains elements in sorted order.

``` java
Set<String> items = new HashSet<>();

items.add("Shell");
items.add("Shell");   // repeated value is ignored
```

### Processing Elements --- `Queue` and `Deque`

Queues are useful when elements need to be processed according to a
defined sequence. A conventional queue follows **FIFO (First In, First
Out)** behavior.

-   `ArrayDeque` --- efficient implementation for queue and double-ended
    queue operations.
-   `LinkedList` --- can also be used for queue and deque functionality.
-   `PriorityQueue` --- retrieves elements according to priority.

``` java
Queue<String> jobs = new ArrayDeque<>();

jobs.offer("first");
jobs.offer("second");

String nextJob = jobs.poll();
```

### Key-Based Storage --- `Map`

A `Map` associates keys with values. Each key can identify at most one
mapping.

-   `HashMap` --- hash-based storage without guaranteed ordering.
-   `LinkedHashMap` --- preserves insertion order and can support
    access-order behavior.
-   `TreeMap` --- keeps entries ordered by key.

``` java
Map<String, Integer> marks = new HashMap<>();

marks.put("Empi", 90);
marks.put("Aarav", 95);
```

`Map` is part of the Collections Framework, but it does not extend the
`Collection` interface because it stores **key-value associations**
rather than standalone elements.

### Collection Selection Guide

  -----------------------------------------------------------------------
  Structure               Best suited for         Examples
  ----------------------- ----------------------- -----------------------
  `List`                  Ordered data where      `ArrayList`,
                          duplicates may occur    `LinkedList`

  `Set`                   Keeping only distinct   `HashSet`,
                          values                  `LinkedHashSet`,
                                                  `TreeSet`

  `Queue` / `Deque`       Sequential or           `ArrayDeque`,
                          priority-based          `PriorityQueue`
                          processing              

  `Map`                   Associating keys with   `HashMap`,
                          corresponding values    `LinkedHashMap`,
                                                  `TreeMap`
  -----------------------------------------------------------------------

## 2. Handling Failures, Recording Activity, and Finding Bugs

Exceptions, logging, and debugging all contribute to reliable software,
but they serve different purposes.

-   **Exceptions** represent abnormal execution conditions.
-   **Logging** records application behavior.
-   **Debugging** investigates the underlying cause of defects.

### Managing Exceptional Situations

Java provides `try`, `catch`, `finally`, `throw`, and `throws` for
responding to exceptional conditions.

``` java
try {
    String data = Files.readString(path);
    process(data);
} catch (IOException ex) {
    logger.log(Level.SEVERE, "Could not load file: " + path, ex);
}
```

### Checked and Unchecked Exceptions

**Checked exceptions** must be handled or declared by the programmer.

Examples:

-   `IOException`
-   `SQLException`

**Unchecked exceptions** are associated with `RuntimeException` and do
not have the same compiler requirement.

Examples:

-   `NullPointerException`
-   `IllegalArgumentException`
-   `IndexOutOfBoundsException`

Serious JVM conditions such as `OutOfMemoryError` are also unchecked,
but they are `Error` conditions rather than ordinary application
exceptions.

### Recording Application Activity with Logging

Logging creates a record of important application events and is
particularly useful when diagnosing problems after a program has been
deployed.

Common logging technologies include:

-   `java.util.logging`
-   Log4j 2
-   SLF4J

Common categories include `DEBUG`, `INFO`, `WARN`, and `ERROR`.

``` java
logger.info("Processed {} entries for account {}", count, accountId);
```

Logs should contain useful diagnostic information while avoiding
confidential details such as passwords, authentication tokens, and
secret keys.

### Techniques for Locating Defects

Useful debugging approaches include:

-   IDE breakpoints
-   Step into, step over, and step out
-   Variable and expression inspection
-   Call-stack examination
-   Conditional breakpoints
-   Exception breakpoints
-   Thread and memory inspection
-   `jdb`
-   Focused tests
-   Targeted diagnostic logging

In short:

-   **Exception →** indicates that an abnormal condition occurred.
-   **Logging →** preserves evidence about program activity.
-   **Debugging →** investigates the reason behind incorrect behavior.

## 3. Responding to User Actions in AWT and Swing

Graphical Java applications are event-driven. An **event** represents an
action or state change, such as a button click, key press, mouse action,
focus transition, or window operation.

AWT and Swing mainly use the **delegation event model**. A component
produces an event, Java creates an event object, a suitable listener is
registered, and the listener performs the required response.

### Basic Event-Handling Example

``` java
JButton submitButton = new JButton("Submit");

submitButton.addActionListener(e -> {
    submitForm();
});
```

Here:

-   `JButton` is the source of the interaction.
-   `ActionEvent` represents the user's action.
-   `ActionListener` receives the event.
-   The lambda expression contains the response logic.

### Common Event and Listener Combinations

  -----------------------------------------------------------------------
  Event                   Listener                Typical trigger
  ----------------------- ----------------------- -----------------------
  `ActionEvent`           `ActionListener`        Button or menu action

  `MouseEvent`            `MouseListener`         Mouse click or press

  Mouse movement          `MouseMotionListener`   Movement or dragging

  `MouseWheelEvent`       `MouseWheelListener`    Wheel rotation

  `KeyEvent`              `KeyListener`           Keyboard input

  `WindowEvent`           `WindowListener`        Window action or state
                                                  change

  `FocusEvent`            `FocusListener`         Focus gained or lost

  `ItemEvent`             `ItemListener`          Selection changes

  `ComponentEvent`        `ComponentListener`     Moving or resizing
                                                  components
  -----------------------------------------------------------------------

For Swing text components, `DocumentListener` is normally used when the
program needs to observe changes to the underlying document content.

### Reducing Listener Boilerplate with Adapters

Some listener interfaces contain several methods. Adapter classes
provide empty implementations for those methods, allowing only the
required callback to be overridden.

``` java
frame.addWindowListener(new WindowAdapter() {

    @Override
    public void windowClosing(WindowEvent e) {
        confirmExit();
    }

});
```

### Keeping the Swing Interface Responsive

Swing event handlers generally execute on the **Event Dispatch Thread
(EDT)**. Long-running work inside an event callback can make the
interface appear frozen.

For expensive background operations, `SwingWorker` can be used so that
the interface remains responsive while background processing occurs.

## 4. Designing a Master-and-Information View

A **master-detail interface** divides related information into two
connected areas.

The **master section** presents a collection of objects, while the
**detail section** displays information about the currently selected
object.

This pattern is commonly found in:

-   Contact managers
-   Email programs
-   File browsers
-   Inventory systems
-   Product-management applications

### Useful Swing Components

A Swing implementation can combine:

-   `JList` or `JTable` --- displays the collection.
-   `JPanel` --- contains detailed information.
-   `JSplitPane` --- separates the master and detail areas.
-   `ListSelectionListener` --- responds when the selected item changes.

``` java
JList<Customer> customerList = new JList<>(customerModel);

JPanel informationPanel = createInformationPanel();

JSplitPane splitView = new JSplitPane(
    JSplitPane.HORIZONTAL_SPLIT,
    new JScrollPane(customerList),
    informationPanel
);

customerList.addListSelectionListener(e -> {

    if (!e.getValueIsAdjusting()) {
        displayCustomer(customerList.getSelectedValue());
    }

});
```

The selected object should ideally be represented in the application's
**model** rather than being reconstructed from text displayed in the
GUI.

Separating data from presentation makes the application easier to
maintain and extend.

For smaller displays, the master and detail portions can also be
presented separately instead of remaining side-by-side.

## 5. Main Takeaways for Assessment Preparation

-   Choose `List`, `Set`, `Queue`/`Deque`, or `Map` according to the
    operation the program requires.
-   `Map` belongs to the Collections Framework but does not implement
    `Collection`.
-   Checked exceptions must be handled or declared; unchecked exceptions
    do not have that compiler requirement.
-   Logging records application behavior, whereas debugging investigates
    the source of faults.
-   Swing and AWT use event sources, event objects, and listeners
    through the delegation event model.
-   Event callbacks should generally remain short so the Event Dispatch
    Thread stays responsive.
-   Adapter classes are useful when a listener contains many callbacks
    but only a few are relevant.
-   A master-detail layout connects a selected object in one area with
    related information in another.
-   Separating application data from GUI presentation generally produces
    cleaner and more maintainable software.
